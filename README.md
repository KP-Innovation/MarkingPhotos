# ป้ายเลขที่งาน (MarkingPhotos)

เว็บแอปมือถือสำหรับถ่ายรูปตัวอย่างทดสอบ **พร้อมป้ายเลขที่งานในภาพเดียว**
แทนการวางป้ายจริงตอนถ่าย — ต่อยอดจากโปรแกรมพีซี `PlateStamper`

รหัสเป็นรูปแบบ `XX-YYMM-NNNN`
`XX` = ประเภทงานทดสอบ · `YY` = ปี · `MM` = เดือน · `NNNN` = ลำดับงานในเดือนนั้น

**พิมพ์ทั้งก้อนไปเลย** เช่น `LP-2609-0045` ไม่ต้องแยกช่อง แอปแกะให้เอง
พิมพ์ติดกันแบบ `LP26090045` ก็ได้ เดี๋ยวเติมขีดให้
ถ้าผิดรูปแบบ (ไม่มีขีด / เลขไม่ครบ) จะเตือนใต้ช่อง แต่ยังถ่ายต่อได้ ไม่บล็อก

## ชื่อไฟล์

`เลขงาน` + `ประเภทรูป` เช่น `LP-2609-0045_Front-Ruler.jpg`
ประเภทรูปเลือกจากปุ่มในหน้าตรวจรูป แตะซ้ำที่ปุ่มเดิม = ยกเลิก แล้วได้ `LP-2609-0045.jpg` เฉย ๆ

ประเภทที่มี: `Front` · `Front-Ruler` · `Rear-Ruler` · `Horizental-Side` · `Vertical-Ruler`
(แก้รายการได้ที่ตัวแปร `PHOTO_TYPES` บนสุดของ `js/app.js`)

> **หมายเหตุสำคัญ:** ชื่อไฟล์นี้ใช้ได้จริงบน Android และเครื่องคอม
> แต่ **iOS Photos ไม่เก็บชื่อไฟล์** พอเซฟเข้าอัลบั้มชื่อจะหาย เหลือแค่ป้ายที่ฝังอยู่ในรูป
> ถ้าต้องการชื่อไฟล์จริง ๆ บน iPhone ให้เลือก "Save to Files" แทน "Save Image"

## ป้ายอยู่ตรงไหน — เลือกได้ 2 แบบ

| แบบ | หน้าตา | เหมาะกับ |
|---|---|---|
| **ป้ายใต้ภาพ** *(ค่าตั้งต้น)* | ต่อแถบพื้นเข้มใต้รูป แล้ววางป้ายกลางแถบ **รูปไม่ถูกป้ายบังเลยสักพิกเซล** | งานทั่วไป — ไม่ต้องกะระยะหลบป้ายตอนถ่าย |
| **ป้ายในภาพ** | ป้ายทับอยู่บนรูปแบบโปรแกรมพีซี ลากย้าย/ย่อขยายได้ มีปุ่มหาที่ว่างอัตโนมัติ | เวลาต้องการให้ป้ายอยู่ในเฟรมรูปจริง ๆ |

สไลเดอร์เดียวกันคุมคนละอย่างในสองแบบ: แบบแถบคุม **ความสูงแถบ** (6–28% ของความสูงรูป
วัดจากความสูงเสมอ รูปตั้งกับรูปนอนจึงได้แถบหนาเท่ากัน) แบบทับภาพคุม **ความกว้างป้าย** เหมือนเดิม

## รูปเข้าได้สองทาง

| ทาง | ได้อะไร |
|---|---|
| **ถ่ายรูป** | เรียกแอปกล้องของเครื่อง ได้ทั้งคุณภาพเต็มและสัดส่วนจริงตามที่กล้องนั้นถ่ายมา |
| **เลือกรูปที่มีอยู่แล้ว** | หยิบจากอัลบั้มหรือโฟลเดอร์ในเครื่อง |

ทั้งสองทางจบที่หน้าตรวจรูปหน้าเดียวกัน สลับแบบป้ายและปรับขนาดได้จนกว่าจะกดบันทึก
โปรแกรมจำรหัส แบบป้าย ตำแหน่ง และขนาดล่าสุดไว้ให้

### เคยมีโหมด "กล้องสด" — ถอดออกแล้ว 2026-08-25

เวอร์ชันก่อนมีกล้องในตัวแอป (`getUserMedia`) ที่เห็นป้ายลอยอยู่ในภาพตั้งแต่ตอนเล็ง
แต่ภาพที่ได้สู้กล้องเนทีฟไม่ได้จริง ๆ: ไม่ผ่าน Smart HDR / Deep Fusion, iOS ไม่ให้สั่งซูมกับ
exposure จากฮาร์ดแวร์, และมุมมองแคบกว่ากล้องหลักเพราะโค้ดล็อกกรอบไว้ที่ 1:1 ตายตัว
ถอดออกทั้งหมดเพื่อให้เหลือทางเดียวที่ให้ภาพดีที่สุดเสมอ — โค้ดเดิมยังอยู่ในประวัติ git

## สัดส่วนภาพ เลือกได้

แถว **สัดส่วนภาพ** ในหน้าตรวจรูป: `เต็มภาพ` (ค่าตั้งต้น) · `1:1` · `4:3` · `16:9`

- เป็นการ **ตัดกลางภาพล้วน ๆ** ไม่มีการยืดหรือบีบไม่ว่ากรณีใด
  (`drawPhotoInto()` ใช้ scale ตัวเดียวกันทั้งแกน x และ y ตามนิยาม)
- สัดส่วน **พลิกตามแนวของภาพเอง** — รูปนอนได้ 4:3 รูปตั้งได้ 3:4
  หมุนเครื่องหรือกดหมุน 90° แล้วพื้นที่ภาพเท่าเดิม ไม่ค้างแนวเดิมจนต้องบีบ
- ค่าตั้งต้นคือ **เต็มภาพ** = ไม่ตัดอะไรเลย ได้สัดส่วนตามที่กล้องของเครื่องให้มา
- ป้ายวางบนรูปหลังตัดแล้ว ขนาดจึงตรงกับที่ตั้งไว้

### เลื่อนกรอบเองได้ ไม่ใช่บังคับตัดกลาง

รูปดิบถูกเก็บไว้ทั้งใบ การตัดตามสัดส่วนเกิดตอนแสดงผลและตอนบันทึกเท่านั้น
หน้าตรวจรูปจึงยังมีเนื้อภาพรอบ ๆ ให้เลือกใหม่ได้ ไม่ต้องถ่ายให้ตรงเป๊ะครั้งเดียวจบ

- **ลากรูป** = เลื่อนกรอบไปครอบส่วนที่ต้องการ
- **หยิกสองนิ้ว** = ซูมกรอบเข้า (สูงสุด 6 เท่า ขยายเกินรูปไม่ได้)
- ปุ่ม **กรอบกลาง** = กลับไปกึ่งกลางแบบไม่ซูม
- เริ่มต้นที่กลางภาพเสมอ
- ใช้ได้ทั้งรูปจากกล้องเครื่องและรูปจากแกลเลอรี
- กด **หมุน 90°** แล้วจุดกึ่งกลางกรอบหมุนตามไปด้วย ส่วนที่เลื่อนไว้ไม่หาย
- เก็บเป็น "จุดกึ่งกลาง + ระดับซูม" เทียบสัดส่วนรูป (`state.crop`) เปลี่ยนสัดส่วนแล้วยังอ้างจุดเดิมได้

### พรีวิวต้องตรงกับไฟล์ที่บันทึก — กับดักที่เคยพลาด

เคยมีบั๊กว่า "จัดป้ายบนจอไว้อย่างหนึ่ง เซฟออกมาได้อีกอย่าง" ต้นเหตุคือ `applyShot()`
คิดที่ว่างจาก `stage.clientHeight` ทั้งก้อน โดยไม่หักบรรทัดคำใบ้ที่อยู่ใต้กล่อง
กล่อง `.shot` เลยถูกสั่งให้สูงเกินที่มีจริง แล้ว flex ก็บีบมันเตี้ยลงเงียบ ๆ
(สั่ง 347px ได้จริง 330px) กรอบภาพจึงผิดสัดส่วน — วัดได้ 1.402 ทั้งที่รูปเป็น 1.333 —
แล้ว `object-fit: cover` ก็ตัดหัวท้ายรูปทิ้งไปข้างละ 2.45% เฉพาะในพรีวิว
ส่วนไฟล์ที่บันทึกได้ภาพครบ ป้ายกับภาพจึงเลื่อนไม่ตรงกัน และป้ายยังเพี้ยนขนาดไปอีก 5%

กฎที่ตามมา (ห้ามถอยกลับ):

- `stageRoom()` หักความสูงพี่น้องในเวทีกับ `gap` ออกก่อนเสมอ
- `.shot { flex: 0 0 auto }` — ห้ามให้ flex บีบกล่องนี้แม้แต่พิกเซลเดียว
- ความสูงแถบป้ายสั่งเป็น **px** ไม่ใช่ `%` เศษจะได้ไม่ไปโผล่ที่กรอบภาพ
- `.frame canvas` ใช้ `object-fit: fill` ไม่ใช่ `cover` — ถ้ากล่องเพี้ยนขึ้นมาจริง
  ให้มันยืดนิดเดียวซึ่งเห็นได้ ดีกว่าตัดภาพทิ้งเงียบ ๆ แล้วพิกัดป้ายเพี้ยนตาม
- แก้อะไรแถวนี้ต้องวัดซ้ำว่า `frame` ที่แสดงจริงมีสัดส่วนเท่ากับ canvas เป๊ะ

## ข้อจำกัดที่แก้ไม่ได้ (เป็นข้อจำกัดของ iOS ไม่ใช่ของโค้ด)

- **บันทึกลงอัลบั้มอัตโนมัติไม่ได้บน iPhone** — เว็บไม่มีสิทธิ์เขียนลง Photos โดยตรง
  แอปจะเปิด share sheet ให้ ต้องแตะ **"Save Image"** อีกหนึ่งครั้ง
  บน Android ไฟล์จะลงโฟลเดอร์ดาวน์โหลดและโผล่ในแกลเลอรีเอง
- **iOS ไม่เก็บชื่อไฟล์ที่เราตั้ง** เมื่อรูปถูกบันทึกลง Photos ชื่อ `เลขงาน_ประเภทรูป.jpg`
  จึงมีผลจริงบน Android และคอมเท่านั้น
- ต้องเปิดผ่าน **HTTPS** เท่านั้น (localhost ก็ได้ตอนพัฒนา)

## ติดตั้งบนมือถือ

เปิด URL ในเบราว์เซอร์ → แชร์ → **Add to Home Screen** → ได้ไอคอนแอปเหมือนแอปทั่วไป
กล้องใช้งานได้ในโหมด standalone (iOS 14.3 ขึ้นไป)

## โครงไฟล์

```
index.html              2 หน้าจอ: กรอกรหัส / ตรวจรูป
style.css               .shot = ภาพ + แถบป้าย (คือสิ่งที่จะได้เป็นไฟล์), .frame = พื้นที่ภาพล้วน
js/plate.js             วาดป้ายจากรหัส — พอร์ตตรงจาก plate.py ค่าคงที่เดิมทุกตัว
js/autoplace.js         หาพื้นที่ว่างในรูป — พอร์ตจาก compose.py (subject_mask + auto_position)
                        ใช้เฉพาะแบบ "ป้ายในภาพ"
js/app.js               สถานะ การตัดกรอบ การลาก/ย่อขยายป้าย และการบันทึก
                        shotLayout() คำนวณกล่องภาพ+แถบ ใช้ร่วมกันทั้งพรีวิวและไฟล์จริง
                        stageRoom() หาที่ว่างจริงของเวที — อย่าแก้ถ้ายังไม่ได้อ่านหัวข้อพรีวิวข้างบน
assets/glyphs/*.png     รูปตัวอักษรจริง 37 ตัว (0-9, A-Z, dash) ยกมาจาก PlateStamper
assets/metrics.json     ความกว้าง/สูง/แนวบรรทัดของแต่ละตัวอักษร
assets/fonts/*.woff2    ฟอนต์ Anuphan (ไทย+ละติน) เก็บไว้เอง ใช้ได้ตอนออฟไลน์
sw.js                   แคชไว้ใช้ตอนสัญญาณไม่ดี
```

ป้ายไม่ได้เจนจากฟอนต์ แต่ต่อจาก **รูปตัวอักษรจริง** ที่ครอปมาจากป้ายของจริง
ป้ายที่ได้จึงหน้าตาเหมือนป้ายที่เคยวางถ่ายเป๊ะ

## ขึ้นคลาวด์ (Cloudflare Pages)

แอปนี้ประมวลผลบนเครื่องทั้งหมด เป็น static site ล้วน ไม่มี Worker ไม่มีฐานข้อมูล

1. Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git
2. เลือก repo `KP-Innovation/MarkingPhotos`
3. Build command: *(เว้นว่าง)* · Build output directory: `/`
4. Deploy — ได้ HTTPS ฟรี

## รันทดสอบในเครื่อง

```bash
python -m http.server 8777
# เปิด http://127.0.0.1:8777/
```
